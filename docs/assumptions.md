# Assumptions and interpretation boundaries

The checks answer specific file questions. They do not establish that a sample is biologically correct. This table makes both scientific assumptions and pragmatic software choices explicit.

| Assumption or choice | Rationale and supporting evidence | What is checked | Consequence if it fails |
| --- | --- | --- | --- |
| The caller supplies the intended files and sample labels. | A manifest makes file selection explicit; names alone cannot authenticate sample identity. | Required fields, unique sample labels, resolved paths, and file existence are checked. Biological identity is **not verified**. | A valid report can describe the wrong sample. Confirm origin independently. |
| Inputs use the declared DNA alphabet. | Restricting to `ACGTRYSWKMBDHVN` gives clear symbol accounting, using [NCBI's ambiguity table](references.md#ncbi-codes). Rejecting U and gaps is a project choice, not a universal FASTA rule. | Unsupported symbols and empty records fail. | Legitimate RNA-letter, aligned, or protein files are rejected; they require a different parser contract. |
| FASTQ quality characters use Phred+33. | [Cock et al. (2010)](references.md#cock-2010) describe incompatible historical encodings. [ENA documentation](references.md#ena-format) declares Phred+33 for archive-generated FASTQ. | The declaration and printable bounds are checked. No certain encoding inference is made from the characters. | An incorrect declaration can yield plausible but wrong scores. User-supplied files need independent encoding evidence. |
| Quality-implied probabilities are meaningful for the supplied scores. | The Phred equation defines the calculation. Good calibration is needed to interpret the sum as an expected error count for these data. | Arithmetic is checked against known examples. **Calibration and actual errors are untested** because no truth reference is supplied. | Expected-error summaries can misrepresent empirical error. No independence assumption is needed merely to sum marginal probabilities. |
| Base-weighted and per-cycle summaries address the intended question. | Equal weight per position gives a file-level mean; late cycles should include only reads reaching that position. | Integer counters and explicit denominators; rounded outputs are not reused to calculate totals. | Variable lengths can change which reads contribute late in a plot; patterns should not automatically be assigned a biological cause. |
| Excluding all ambiguity symbols is an appropriate declared GC convention. | It avoids inventing underlying bases. This includes S and W even though each constrains GC status. | GC uses only A/C/G/T and is undefined (`null`) without them. | Comparisons with tools that resolve ambiguity differently can disagree without either arithmetic being wrong. |
| User grouping labels are suitable for per-sample length summaries. | Grouping is operational metadata. N50 is a useful arithmetic example, using the [NCBI convention](references.md#ncbi-assembly). | Both pooled and grouped summaries are reported. Whether records form an assembly is **not established**. | A larger N50 cannot demonstrate correctness, completeness, or organism purity. |
| Supported matching header keys are useful for positional mate checks. | The [Illumina layout](references.md#illumina-format) and [SeqKit guide](references.md#seqkit-guide) motivate explicit naming rules. This implementation adopts its own restricted grammar. | Equal nonzero record counts, order, keys, and expected mate numbers are checked. Duplicate keys across positions and biological pairing are not verified. | Matching names can still accompany unrelated sequences; nonmatching but valid historical conventions are rejected. |
| The first 1,000 archived reads are enough for a small real-file demonstration. | A bounded prefix keeps the repository runnable without a large download. This is a convenience choice, with no representativeness claim. | The supplied 1,000 records, file fingerprints, and known output counts are checked locally. | Its means or proportions cannot estimate full-run quality or support between-condition comparisons. |
| The archive's organism, layout, and study mapping are correct. | Source labels are retained with accessions and provenance rather than re-inferred from sequence summaries. | Earlier archive retrieval and hashes are preserved; this review's access limits are recorded in the [reference audit](reference-audit.json). Organism identity and complete-run properties are **not independently validated**. | Incorrect archive labels would remain incorrect in a structurally valid report. |
| The chosen lock is a trusted reference for bytes. | SHA-256 can detect a change relative to that reference. Historic whole-download MD5 checks address transfer equality, not authenticated origin. | Locks are verified before QC and against raw bytes consumed, including gzip bytes. | Replacement of both lock and data can go undetected. Recompression can fail a lock even when decoded reads are unchanged. |
| Files remain stable and the filesystem can complete output replacement. | Streaming and staged writes avoid storing all FASTQ records and preserve earlier reports on validation failure. They are not a filesystem-wide transaction. | Tested validation failures leave earlier reports intact; exit status reports expected failures. | Concurrent changes or operating-system errors during replacement may leave partial output. Keep inputs stable and check the status. |
| Resource limits are suitable for the job. | FASTQ has a one-million-symbol per-read cap; FASTA snapshots all bytes and records; per-read JSONL can be large. These are software limits, not biological boundaries. | Boundary cases and malformed records have tests. Whole-run performance and all platforms are not benchmarked. | Large inputs can exceed memory/disk/time expectations or a valid unusually long read can be rejected. |

The [practical-use guide](practical-use.md) shows a file handoff within these limits. Passing a checksum, a parser, and a mate-name check answers three different questions; none supplies a biological validation by itself.
